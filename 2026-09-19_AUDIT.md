## 3. Wrapper-replaceable rules

`bowtie2_build`'s `shell:`
(`bowtie2-build --threads {threads} {input.fasta} {params.index_name} &> {log}`)
hand-rolls what the official **`bio/bowtie2/build`** wrapper already does —
same 6-file index output, `extra`/thread support, auto conda env via
`--use-conda`. Confirmed via the wrapper docs (latest at
`v7.9.0/wrappers/bio/bowtie2/build.html`). Recommend migrating this rule to
the wrapper — not applied, left for explicit approval.

## 4. Rule-authoring hygiene

- `bowtie2_build` uses an inline `lambda` in `params`
  (`index_name=lambda w, output: output[0][: -len(".1.bt2")]`) — a
  legitimate, common Snakemake idiom for deriving a basename from a
  `multiext` output; flagged per checklist, no change recommended unless
  desired.
- `combine_sequences` declares
  `log: logs/combine_sequences/combine_sequences.log` but
  `combine_sequences.py` never redirects `sys.stderr` to it — any traceback
  from the script goes to the terminal/snakemake log instead of the declared
  log file. Fix candidate: add
  `sys.stderr = open(snakemake.log[0], "w", buffering=1)` near the top of
  the script.
- No absolute paths, no named conda envs, no `conda:`+`run:` combination,
  consistent `_` separators. Clean otherwise.
